设计说明 · mp-weixin 微信小程序端

依据《2026-10-15-任务撮合平台-总体设计》§5.15.2 端能力矩阵、§5.15.3 信息架构与页面清单、§4.9.2 等级与权益矩阵、§4.10.3-4 任务形态与计酬方式、§4.11.2 任务状态全集。 端定位：获客与轻操作端（⛔ 不承担专业接单方的交付场景）。

i这是什么

  • 本页是静态 HTML 原型（设计稿），不是可运行工程，也不接任何真实接口/数据。
  • 单文件完全自包含：所有 CSS/JS 内联，⛔ 无任何外部 CDN / 字体 / 图片引用，断网双击即可打开。
  • 图标全部用 emoji 或纯 CSS 图形绘制；价格、距离、时间、订单号均为拟真示例数据。
  • 每屏都是真实尺寸的 375 × 812 手机框：状态栏 + 导航栏 + 内容区 + 底部 Tab 栏。
  • 点击带蓝色描边的元素可跳转到对应屏（点顶部「显示热区」可看全部热区）。

!小程序的三个硬限制（§5.15.2）

  • ① 不能大文件分片：wx.uploadFile 不支持分片与断点续传 → 本原型在屏 5 提交报价、屏 8 交付提交 显式写死「单文件 ≤20MB，超大交付物请用电脑端」，并给出「复制电脑端链接」的迂回方案。
  • ② 不能系统级静默推送：只有订阅消息，一次性授权、每次都要用户主动订阅、有模板与次数限制 → 本原型在屏 4A 抢单成功弹层内做「订阅开奖/中标通知」的场景化请求（有动力的时刻才请求）。
  • ③ 不能使用支付宝：小程序内仅 wx.requestPayment（微信 JSAPI）→ 本原型屏 5（报价托管）与屏 11 钱包标注「仅支持微信支付」，提现引导至 App / 电脑端。
  • 另两条影响设计的限制：WS 全局最多 2 条连接、切后台断开（屏 9/10 文案提示「回到前台自动补拉离线消息」）；定位需授权、可降级（屏 3 签到、屏 13 隐私说明）。

#操作方式

  • 顶部索引条：点任意「屏 N」跳转（锚点），滚动时自动高亮当前屏。
  • 仅看单屏：只显示当前一屏，可用 ← → 方向键翻屏，右下角也有翻屏按钮。
  • 热区跳转示例：屏 1 任务卡 → 屏 2/3；屏 3「立即抢单」→ 屏 4；屏 2「立即报价」→ 屏 5；屏 5「提交报价」→ 屏 6；屏 7 订单卡 → 屏 8；屏 9 会话 → 屏 10。

  • 手机框内容可内部滚动（真实小程序页面亦如此），滚轮悬停在框内即可。

移动端如何渲染状态标签
1）颜色 = 域，形状 = 阶段。同一域内用同一色系：招募域蓝、履约域蓝→橙→红递进（越接近违约越红）、 收尾域绿、终态灰。列表卡片只用小圆角标签（高度 20px），详情页用实心标签 + 状态码。
2）主文案用中文，状态码仅作辅助。如「履约中 IN_PROGRESS」， 状态码用等宽小字，便于客服与研发对单。
3）需要动作的状态必须带 CTA。待开始→扫码签到、履约中→去交付、待验收→催一催、返工→重新交付、待托管→去支付。
4）时间敏感状态必须带倒计时。竞价中/待选标（剩余报价时间）、履约中（交付倒计时）、待验收（自动验收倒计时）； ≤24 小时转红色。
5）⛔ 终态不再展示任何操作按钮，仅保留「查看详情 / 复盘 / 申诉（7 天内）」；
6）⛔ 争议中（DISPUTED）必须在订单卡顶部加红色横幅，并冻结相关份额，避免用户误以为还能正常结算。
7）状态由服务端下发枚举，客户端只做映射（颜色/文案/CTA 三张映射表），⛔ 不在端上拼状态字符串。
