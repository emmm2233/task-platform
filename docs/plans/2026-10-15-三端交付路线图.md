## 四、⭐ 移动端 W1–W4 做什么（并行成败的关键）

**直接开 uni-app 做页面会空转** —— 核心页面（抢单/报价/交付/钱包）全依赖后端接口，而接口 W5 之后才齐。所以前 4 周安排成「骨架 + 外部流程 + 可 Mock 的页面 + 端适配」：

| 周 | 移动端工作 | 为什么不能推后 |
|---|---|---|
| **W1** | ① uni-app 工程骨架 + 三端构建流水线（小程序 / Android / iOS）<br>② `src/platform/` 四个 adapter 接口定义与 Mock（**支付 / 推送 / 上传 / 定位**）<br>③ ⭐ **启动微信侧外部流程**：小程序账号注册、**服务类目申请**、服务器域名白名单、隐私政策准备 | 小程序账号与类目审核是**外部流程**，周期 1–2 周不可控；`platform/` 层不建，后面页面会到处 `#ifdef` |
| **W2** | 用 Mock 做 **登录 / 任务列表 / 任务详情 / 我的**（占移动端页面 ~30%，且不依赖后端） | 这 4 页与后端接口形态简单，Mock 即可完成 |
| **W3** | **抢单页 + 报价页**（先 Mock，接口一就绪即切换真实） | 抢单是移动端最高频操作，必须最早跑通 |
| **W4** | **支付（JSAPI）+ IM（`wx.connectSocket` 断线补偿）** | 这两块是端适配的重头，且依赖 `platform/` 层（W1 建的） |

**W5 起**：后端接口陆续齐备 → 订单工作台、交付、钱包、信誉分中心、实名等页面进入真实联调，**不再空转**。

> ⭐ **W1 就启动微信侧外部流程**是这次排期里最容易被忽略、却最可能拖垮整体的一点：**代码写完了但类目没过，小程序一样上不了线。**

## 五、uni-app 的代码复用边界（P2/P3 共同前提）

选了 uni-app 后，**小程序与 App 共用一套代码**，但有三处必须分叉：

| 层次 | 复用策略 | 分叉点 |
|---|---|---|
| **页面与组件** | ✅ 一套（小程序与 App 之间） | 无 |
| **状态与请求** | ✅ 一套（Pinia + 请求封装） | 无 |
| **业务逻辑** | ✅ 一套（composables，写成 framework-agnostic 纯函数） | 无 |
| **条件编译** | ⚠️ `#ifdef MP-WEIXIN` / `#ifdef APP-PLUS` | ⛔ **只允许出现在 `src/platform/`**：① 支付（`requestPayment` vs SDK）② 推送（订阅消息 vs 厂商 Push）③ 上传（不可分片 vs 可后台分片）④ 定位与扫码 |
| **构建与发布** | ⛔ 两套流水线 | 小程序走开发者工具上传；App 走云打包 + 应用商店 |
| **与 `web-user` 的关系** | ⛔ **不共享任何 Vue 组件**（uni-app 组件与 Element Plus 不兼容）；✅ **可共享 `packages/shared` 的 TS 类型与纯函数** | — |

> ⛔ **纪律**：CI 加 lint 规则扫描 `src/` 下的 `#ifdef`，出现在 `src/platform/` 之外即构建失败（路线图 R6）。

## 六、三端共享后端的 10 项纪律（谁在哪个任务做）

这 10 项在并行开发下**从"将来补做很贵"升级为"现在不做就会阻塞另外两端"**：

| # | 事项 | 落地任务 | 阻塞谁 |
|---|---|---|---|
| 1 | 所有写接口支持 `Idempotency-Key` | T1（拦截器）+ T3（CI 校验） | mobile（弱网易重发） |
| 2 | 金额用字符串、时间用 ISO-8601 带时区 | T1 | 三端 |
| 3 | 列表分页支持游标 | T12 | mobile（下拉刷新） |
| 4 | 鉴权与端解耦（统一令牌） | T4 | 三端 |
| 5 | **托管创建接口预留 `X-Client` 分支** | **T17**（`PayParamAssembler`） | **mobile 支付无法做** |
| 6 | **WS 协议与端无关 + 序号补偿** | **T28** | **mobile IM 无法做** |
| 7 | 文件上传走「服务端签名 + 客户端直传」 | T2 + T17 | mobile 上传 |
| 8 | 业务字段带 `source_client` | T9 + T17 | 多端归因 |
| 9 | 状态字段足够表达（18 状态 + allowedActions） | T10 | 三端 UI |
| 10 | 端能力矩阵落表 | ✅ **DDL V4 已就绪**（41 条） | 三端 |

**验收动作**：W10 逐条自查，全部通过才允许 P1 上线。
