## 3. ⭐ 反复踩到的缺陷类别（按出现次数）

| # | 类别 | 次数 | 收敛点 |
|---|---|---|---|
| 1 | **`NOT NULL DEFAULT x` 的列插入显式 null → 1048** | **≥14** | `common/db/RowValues`（主表只插有值的列；子表 `nz()`） |
| 2 | **JSON 列不能用普通字符串 / 往返不一致** | 3 | `RowValues.toJson`；参与哈希的值必须取「取回后」的形态 |
| 3 | **测试之间通过持久状态互相污染** | 5 | 一律加 `@BeforeEach` 重置或独占分段 |
| 4 | **随机值空间太小 + 无重试** | 2 | `user_no`(T10) / `task_no`(T15)。⭐ 空间不足时碰撞是**必然**，要加长空间而非只加重试 |
| 5 | **自建父 pom 丢失框架默认值** | 2 | `repackage` 绑定 · `-parameters` |
| 6 | **异常兜底把 HTTP 语义吃掉** | 2 | `AccessDeniedException`→200(T6) · `NoResourceFoundException`→200。均已加显式处理器 |
| 7 | **`queryForObject` 在 0 行时抛异常而非返回 null** | 3 | 「查不到 ≠ 查询失败」。用 `queryForList` 判空 |
| 8 | ⭐ **用脚本改代码，改了但没生效，却打印了成功** | **6** | 见下节 |

### 第 8 类最危险，单列出来

实际形态：

1. `.replaceAll('"PENDING"', '"QUOTED"')` —— SQL 里是**单引号**，只改到 Java 字符串
2. 正则写了 `String column`，文件里实际是 **`String col`**
3. 锚点未命中，**`toJson` 定义没加上**但调用点加上了 —— **增量编译不报错**，`clean` 才暴露
4. 脚本因「文件变了」就打印 ✅，实际只加了一个**用不到的 import**
5. 用正则改核验脚本的检查项，**替换静默未生效**，而实跑用的是内联检查
   —— **差点提交一个内容与实际验证不符的脚本**
6. 删方法时锚点不精确，只删了一半，留下调用已删除方法

⛔ **规则**：用脚本改代码后必须**逐个回读目标位置的真实内容**，不能看脚本输出。
且**改完行为没变化时，第一反应是"改动真的生效了吗"**，而不是「再调一次参数」。
⭐ **删代码比改代码更需要回读** —— 「删多了」和「删少了」都不会立刻显形。

## 4. ⭐ 三条我认为最值钱的工程判断

### ① 状态机的价值不在于允许什么，而在于拒绝什么

T10 把迁移表**条数钉成断言**（`transitionCount() == 38`），实跑报 36 ——
**正是这个断言逼出了我漏掉的 2 条迁移**（文档 #3「审核通过且已托管」的两条分支，
即"发布即托管"这条主路径）。若只测「合法迁移能过」，那 2 条漏掉的永远不会被发现。

### ② 注释不是机制

`NOT NULL` 那个坑踩了 14 次，中间在 T9、T11、T13 各写了一遍注释提醒 ——
**第 10、11、12 次照样踩**。最后是 `RowValues` 这个**代码机制**在收敛它。

> **凡是「我提醒过自己」却还在重复犯的错，就该停下来做工具，而不是再写一遍提醒。**

### ③ 单测覆盖不到的那一层，只能靠"真实启动 + 真实请求"来守

本会话三次证明：
- `CategoryController` 注释说公开、实际 401（单测直接调 Service，**绕过 HTTP 与鉴权**）
- 未映射路径返回 200（异常兜底，**只有打真实接口才看得到**）
- 前端代理配错（**构建通过、单测更没有**）

⇒ 收尾前必须跑一次「清理重建 + 真实启动 + 打真实接口」。

## 5. ⚠️ 我在已提交的代码里写错过的三处（如实记录）

都**看着很合理**，且我都曾当作"设计亮点"汇报过：

1. **「库里刻意没有钱包表、资金不过平台账户、构成二清红线」**（T16）
   —— 完全错误。`wallet_account` / `wallet_txn` / `withdraw_apply` 都在。
   **错因：探查时用了 `wallet` / `wallet_transaction` 两个不存在的表名，
   把「查不到」当成了「不存在」。**
   ⇒ 探查必须先**列出全部表**再挑，⛔ 不要凭记忆拼表名去查。

2. **「这些是公开只读接口，未登录也要能渲染」**（T8 `CategoryController`）
   —— 与实现不符（实际 401）。**单元测试结构上不可能发现**。

3. **「用 `.npmrc` 的 `strict-dep-builds=false` 解决了 pnpm 拦截构建脚本」**（前端脚手架）
   —— 实跑 `pnpm build` 仍 exit 1。真正的原因见 §7。

> **结论越"漂亮"，越该回头核对依据。**

## 7. 环境备忘（本机与设计文档的偏差 + 踩过的坑）

### 工具链
- 无 Docker → 本地 MySQL 8.4 服务 `MySQL84`；Redis 5.0.14.1（`deploy/start-local-redis.ps1`）
- Maven `.tools/apache-maven-3.9.16/` · JDK `C:\Program Files\Java\jdk-21.0.11`
- Node 24 / pnpm 11.3.0 · npmmirror 可达

### ⛔ 硬规则（每条都踩过）
1. **每次 pwsh 调用都要显式 `Set-Location`** —— 每次都是新进程，workdir 回到会话根
2. **Maven 输出写进 UTF-8 文件再读**（控制台是乱码）
3. **多行中文提交信息一律 `git commit -F <文件>`** —— 中文引号会破坏 PowerShell 引号配对
4. **含引号的展示文本用单引号** —— 双引号字符串里写直双引号会让**整个命令一行都不执行**
5. **打接口用 `curl.exe`**，不要 `Invoke-WebRequest`（它会吞掉错误响应体）；
   且中文查询参数要 **URL 编码**，否则容器返回 400（**测量假象，不是缺陷**）
6. **改了安全配置/路由后必须 `package` 再验证** —— 只跑 `mvn test` 用的是旧 jar
7. **提交前必须过门禁**，且脚本里要有守卫：
   ```powershell
   & node tools/check-consistency/check.mjs
   if ($LASTEXITCODE -ne 0) { '门禁红，拒绝提交'; exit 1 }
   git commit ...
   ```
   ⛔ 本会话**两次**带着红门禁提交（T5、T26），都是因为脚本里缺这道守卫。
   **规则写在提交信息里不会自动生效。**
8. **pnpm 11 的放行键是 `allowBuilds`，不是 `onlyBuiltDependencies`**（旧键名不生效），
   且**每一项都要显式 `true`/`false`**；`allowBuilds` 必须写在**仓库根**的
   `pnpm-workspace.yaml`（pnpm 只认**最近**的 workspace 根 ——
   子项目下若有 `pnpm-workspace.yaml` 会让根配置失效）
9. **`@dcloudio/*` 的 `latest` 是 Vue2 线** —— 必须全部 pin 到 `vue3` 标签的同一版本
   （`npm view @dcloudio/uni-app dist-tags`）
