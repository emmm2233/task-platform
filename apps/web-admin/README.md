# web-admin（运营管理台）

Vite + Vue 3 + TypeScript。**管理端没有匿名态** —— 所以第一屏就是登录。

## 跑起来

    pnpm install          # 在【仓库根】执行（workspace）
    pnpm --filter web-admin dev      # http://127.0.0.1:5175

后端要同时在跑。开发期由 Vite 代理 `/api` 到 8080。

## 首屏验证的是哪条路径

⭐ **登录 → 拿令牌 → 调受保护接口**。这是管理端与用户端最大的差别：
用户端大厅是匿名的，管理端没有匿名态，**登录链路必须先跑通**，
后面的审核台（内容审核 / 实名审核 / 敏感词 / 工单）才有意义。

## 与 web-user 的复用与差异

| 项 | 做法 |
|---|---|
接口类型 | 来自 `@task/shared`（⭐ 不再各写一份，避免漂移） |
Vite 代理 | 同一套取舍：代理 `/api`，前端不写绝对地址（免 CORS） |
令牌注入 | ⭐ 统一在 `api/adminClient.ts` 注入，⛔ 不让每个页面自己拼 header —— 漏一处就是一个静默的 401 |
令牌失效 | `code === 20001` 时就地清掉令牌，避免界面停在"已登录"的假象 |

## ⚠️ 当前的安全简化（如实记录，别当成已完成）

令牌存在 **sessionStorage**。选它而不是 localStorage 是因为管理台常在共用电脑上使用，
关掉标签页即失效更安全。**但真正的生产方案是 HttpOnly Cookie + CSRF** ——
sessionStorage 仍可被 XSS 读取。这条是 Phase 1 的简化，不是终点。


## 端到端核验（可复跑）

    powershell -File scripts/verify-e2e.ps1

验的是**登录链路的可达性**（管理端的存在前提）。本机实测（2026-10-15）：

    [OK] /account/profile 无令牌 -> HTTP 401
    [OK] /op 域 无令牌          -> HTTP 401
    [OK] /admin 域 无令牌       -> HTTP 401
    [OK] 登录接口可达           -> HTTP 200
    失败项 = 0

这四条一起才说明问题：**接口确实存在**（否则会像上次那样被异常兜底变成 200）、
**未登录确实进不去**、**运营与管理域确实受保护**。
